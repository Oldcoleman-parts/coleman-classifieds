## F01 — Foundation and platform

### High

- [x] ticket → **[High] core · `app/modules/core/index.js:57-60`, `app/modules/core/events.js:153-160`** — a failed `PAY` is swallowed. Core’s `PaymentReceived` listener calls `transition(PAY)`, but `dispatch()` catches every handler error and logs its name only. A database error, or a payment that arrives after the listing lapsed, leaves the seller charged and the listing not live; the webhook answers 200 and Shopify never retries. → Make the PAY path fail loudly (rethrow so the webhook returns 500) and raise an incident when a paid listing can’t go live. **F01-FIX-1**
- [x] ticket → **[High] platform · `app/modules/platform/services/webhooks.js:56-76`** — the `WebhookReceipt` is committed before the handler runs and removed only in a `catch`. A crash, deploy or timeout mid-handler (or a failing delete at line 70) leaves the receipt, so Shopify’s retry gets 200 and does nothing. For `orders/paid` that is a paid listing that never publishes. → Record `processedAt` after the handler succeeds and treat an unprocessed receipt as retryable. **F01-FIX-2**
