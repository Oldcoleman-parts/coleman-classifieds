- [ ] [Medium] ops · `app/modules/ops/services/facts.js:37-44` (used by `reminders.js:95,120`, `closed-email.js:68`, `hooks.js:24`): `findListings` always returns the same oldest 200 rows (`createdAt asc`, `take: 200`). Rows that were already reminded or emailed, or are still in their grace period, stay in that set, so past 200 the newer listings are never reached. Phase 2 renewal grace has the same limit (security audit, Low, merged here) → filter out finished rows in the query (for example `overdueSince <= now - graceDays`, or no sent marker), order by deadline, and page with a cursor.
- [ ] [Medium] ops · `app/modules/ops/services/facts.js:65-75`, `retire-pages.js:18-31` (security audit): a listing whose retirement keeps failing (for example the redirect create in `publishing/services/retire.js:31-42` throws) keeps its `metaobjectGid` and stays first in the oldest-closed batch of 20. Twenty such listings stop every other page from retiring without notice → count failures and leave a listing out after N, raising a PUBLISHING incident (F08-T2 `raiseIncident`).
- [ ] [Medium] scheduler · `app/modules/scheduler/registry.js:84`, `runs.js:15`: a `?task=` recovery run is saved as a normal `JobRun`, so `getLastRun()` (Health, and the F08-T2 watchdog) reports one task's result as the last full run → store `only`/`partial` on the row and have `getLastRun` skip partial runs.
