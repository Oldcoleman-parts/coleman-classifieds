## Scope

- [ ] A status-driven proxy page in the theme layout (`noindex`, `Referrer-Policy: no-referrer`, mobile first): service info, fee (regular crossed out), one-month duration, rules text, public/private labels, deadlines shown.
- [ ] Form + validation + autosave + photos; INVITED→DRAFT sets `draftDueBy`; an unticked agreement → `TermsAcceptance` → SUBMITTED (NEW).
- [ ] CHANGES_REQUESTED stage showing the staff note and correction deadline → resubmit (CORRECTED).
- [ ] Live stage: “Live until {date}”; immediate price, quantity, availability note and photo removal; title, description and photo additions → `ListingRevision` (the approved version stays live); mark sold and remove (with confirmation). A placeholder for the pay stage (F06).

## Out of scope

- Anything listed in other tickets or features.

## Acceptance criteria

- [ ] A seller can leave and return until the deadline; after it, the closed page shows.
- [ ] Submit is blocked until everything is valid; the rules version and time are recorded.
- [ ] Resubmitting fires the CORRECTED staff notice.
- [ ] Immediate fields update without review; adding a photo doesn’t change the public page before approval; no path adds or replaces merchandise.
- [ ] `npm run test:ai` is green for this feature.

## Notes

_Record decisions (`// DECISION:`), deviations and follow-ups here. Code review and security audits are run on demand (`/review-all`), not per ticket._

- From F02-T2: `Settings.rulesText` is stored as plain text (no `<` or `>`, up to 20,000 characters, LF line breaks). Escape it as HTML when showing it to sellers (and escape Liquid delimiters if the proxy page returns Liquid), keep the line breaks, and store in `TermsAcceptance.rulesVersion` the version the seller was actually shown (`Settings.rulesVersion`, e.g. `v1`).
- From F03-T2: photo storage is ready in `app/modules/media`. Build the two proxy routes (`/apps/classifieds/upload-url`, `/apps/classifieds/upload-complete`) here: check the seller’s link and listing first, rate-limit the POSTs, then call `media.createUploadUrl({ listingId, actor, contentType, byteSize })` and `media.completeUpload({ listingId, photoId, actor })`. Media does **not** check the token; it trusts the `listingId` it is given.
- From F03-T2: in the browser use `uploadPhoto()` and `resizeImage()` from `app/modules/media/client.js` (resize, upload progress). Show photos with `media.listPhotos(listingId)`; its `previewUrl` links are private and last 10 minutes, so never put them on a public page. Reorder, main photo and delete are `media.reorder()`, `media.setMain()` and `media.deletePhoto()`; `deletePhoto()` also takes a live photo off the public site at once.
- From F03-T2: on `ListingWentLive` and `RevisionApproved` media publishes **every** current photo of the listing. A photo added for a pending revision must therefore be deleted with `media.deletePhoto()` if the revision is rejected, so it can never be published later. `media.publish(listingId, { photoIds })` publishes only the named photos.
- From review 1: do F03-FIX-2 (only approved photos may be published) before this ticket; it defines how a revision’s photos are marked approved. F03-FIX-1 (repeated upload completion) should also be done first.
