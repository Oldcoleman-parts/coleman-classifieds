Start with `/implement-ticket F04-T3`. Needs F03-T4 (the `seller_link_request` email).

Added 2026-10-06 while planning F05-T1. Sellers have no account; each listing has its own invitation and private link, and only the link's hash is stored. This page lets a seller who lost their links get working ones by email.

## Scope

- [ ] Proxy page `/apps/classifieds/my-link` (GET form, POST): email field, Turnstile and a honeypot; `noindex`, `Referrer-Policy: no-referrer`, theme layout.
- [ ] POST finds every **open** listing whose invitation went to that address (case-insensitive, trimmed): INVITED, DRAFT, CHANGES_REQUESTED, SUBMITTED, APPROVED_AWAITING_PAYMENT, LIVE, PAUSED. Newest first, at most 20.
- [ ] For each of them a new 32-byte link replaces the old one (only the new hash is stored, so the old link stops working at once), in one transaction, with an `AuditEvent` per invitation (actor SYSTEM, `SELLER_LINK_REISSUED`, no token in it).
- [ ] One `seller_link_request` email with all of them (F03-T4), sent to the invitation's stored address, not the typed one.
- [ ] Always the same reply and the same response shape, whether or not the address is known; nothing is sent when it isn't.
- [ ] Rate limits: per IP, and per email address (at most 3 a day; further requests change nothing and send nothing).
- [ ] Export `getLinkUrl(admin, shop)` from `access/index.js` (the storefront URL of this page) for emails that show the help line.

## Out of scope

- A combined "My listings" page (possible later feature, needs a new kind of token).
- Email codes: confirming one listing on a device still doesn't confirm the others.
- Closed listings (SOLD, EXPIRED, REMOVED, REJECTED, LAPSED) are never included.

## Acceptance criteria

- [ ] A seller with three open listings and one closed one gets one email with three working links; their old links show the invalid-link page.
- [ ] An unknown address gets the same reply, no email and no change.
- [ ] The fourth request in a day for the same address changes nothing and sends nothing; the IP limit gives 429.
- [ ] Turnstile failure or a filled honeypot changes nothing.
- [ ] Log spy: no token or link in logs or audit rows.
- [ ] `npm run test:ai` is green for this feature.

## Notes

_Record decisions (`// DECISION:`), deviations and follow-ups here. Code review and security audits are run on demand (`/review-all`), not per ticket._

- Device credentials, email codes and form tokens are bound to the invitation, not the token, so replacing a link doesn't sign the seller out of a confirmed device.
- Someone who knows a seller's email can trigger new links, but the links only go to the seller's inbox; the daily limit keeps this from becoming a nuisance.
