## Notes

_Record decisions (`// DECISION:`), deviations and follow-ups here. Code review and security audits are run on demand (`/review-all`), not per ticket._

- From F03-T1: the relay uses `notifications.send("buyer_message", to, vars, { replyTo, idempotencyKey })` with `replyTo` = the buyer (placeholders in `app/modules/notifications/registry.js`). It is `sensitive` (the buyer’s words), so it is never stored in the outbox: `send()` returns `{ status: "FAILED" }` if SES is down, and the caller must cope (show the buyer an error or retry later).
- From F05-T2: the held messages screen (`/app/messages`) is built and waits for this module. Export `listHeld()`, `release(id, staff)` and `discard(id, staff)` from `contact/index.js`, each returning `{ changed, listingId }`, and register them with `console.setMessageProvider()` (contract in `app/modules/console/services/providers.js`). Release must change `HELD → RELEASED` atomically and send exactly once; a repeat returns `changed: false`. The real "double release sends once" test belongs here. Console writes the staff audit entry.
- From F01-FIX-5: rate-limit the contact form with `rateLimit(key, { limit, windowMs })` and `clientIp(request)` from `@/modules/platform/index.js` (in memory, one instance). Hash the buyer email before using it in a key; tests call `resetRateLimits()`.
- 2026-10-20 build decisions (`// DECISION:` in code):
  - Blocked attempts (rate limit, honeypot, Turnstile) are turned away and not stored; `BLOCKED` stays unused (`contact/services/pages.js`).
  - Repeat sends: the buyer address's messages in the last 24 h, across all listings, ≥ `repeatThreshold`; links are looked for in the name and the body; keywords are case-insensitive substrings; reasons are codes only (`contact/services/classify.js`).
  - A normal message whose send FAILED is deleted and the buyer asked to retry; a suppressed seller address counts as delivered. A failed release undoes the claim (back to HELD) and throws `ConflictError`; a crash between claim and send leaves it RELEASED unsent (`contact/services/messages.js`).
  - Held and delivered show the buyer the same page; every proxy page is status 200 (F06-FIX-1).
  - Contact keeps its own `facts.js` (reads `Listing`/`Invitation`) and its own Turnstile copy.
- Approved in this ticket outside the module: `notifications.send()` also returns `sesMessageId`; the listing block's reserved slot now links "Contact the seller"; migration `contact_buyer_message_indexes` (indexes only).
