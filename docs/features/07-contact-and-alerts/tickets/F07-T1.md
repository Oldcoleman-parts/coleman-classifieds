## Scope

- [ ] Contact form (name, email, message ≤ 2000, Turnstile, honeypot); rate limits per IP, email and listing; LIVE only.
- [ ] The hold classifier from `Settings.heldMessageRules`; `BuyerMessageHeld` → instant staff notice; release (sends once) and discard actions used by the F05 messages screen.
- [ ] Relay via `buyer_message` (ReplyTo = buyer, CR/LF stripped); logged with the SES message ID.

## Out of scope

- Anything listed in other tickets or features.

## Acceptance criteria

- [ ] A normal message reaches the seller and replies go straight to the buyer; the seller email never appears in the HTML.
- [ ] A message with a link is held, staff are emailed with a working link, release delivers it once, and discard never delivers.
- [ ] Bots and rate-limited sends are rejected; a closed listing refuses messages.
- [ ] `npm run test:ai` is green for this feature.

## Notes

_Record decisions (`// DECISION:`), deviations and follow-ups here. Code review and security audits are run on demand (`/review-all`), not per ticket._

- From F03-T1: the relay uses `notifications.send("buyer_message", to, vars, { replyTo, idempotencyKey })` with `replyTo` = the buyer (placeholders in `app/modules/notifications/registry.js`). It is `sensitive` (the buyer’s words), so it is never stored in the outbox: `send()` returns `{ status: "FAILED" }` if SES is down, and the caller must cope (show the buyer an error or retry later).

Export `listHeld()`, `release(id, staff)` and `discard(id, staff)` from `contact/index.js`, each returning `{ changed, listingId }`, and register them with `console.setMessageProvider()` (contract in `app/modules/console/services/providers.js`). Release must change `HELD → RELEASED` atomically and send exactly once; a repeat returns `changed: false`. The real "double release sends once" test belongs here. Console writes the staff audit entry.
- From F01-FIX-5: rate-limit the contact form with `rateLimit(key, { limit, windowMs })` and `clientIp(request)` from `@/modules/platform/index.js` (in memory, one instance). Hash the buyer email before using it in a key; tests call `resetRateLimits()`.
