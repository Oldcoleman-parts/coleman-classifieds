### Decisions (F07-T2)

- Confirm and unsubscribe links in emails open a page with a button (approved by the user: email scanners that open links can't confirm or unsubscribe anyone). The `List-Unsubscribe` one-click POST unsubscribes straight away.
- Client decision (2026-10-26): OCP dropped the daily digest; each new listing is emailed to subscribers as soon as it first goes live (the `alerts_digest` template, sent with one listing).
- Sending: the go-live handler queues the row and starts the send without awaiting it (`services/send.js`), so the payment webhook never waits. The hourly `alerts.send-pending` sweep sends rows still unsent after 15 minutes, at most 10 listings a run. Each email's key is `alerts_new:<listingId>:<subscriberId>`, so concurrent runs never double-send (no claim column). A sold, expired or removed listing is dropped; a LIVE listing without its storefront page waits; rows older than 3 days are dropped. A failed send isn't retried (the alerts templates never store their data); notifications reports it. Turning alerts back on doesn't start a sweep; the next hourly run sends.
- Complaints and hard bounces: at send time a suppressed address is marked unsubscribed (`via SUPPRESSED`). No change to notifications.
- Alerts switch off: signup, confirm and resubscribe 404, the theme signup is hidden (shop metafield `classifieds.alerts_enabled`), nothing is queued and alerts pause; queued rows are kept. Unsubscribe always works. The listeners are always registered (the switch can change at runtime) and check `isEnabled("alerts")`.
- The theme block posts only the email; the app's page then shows Turnstile, so Cloudflare's script never loads on theme pages.
- Unsubscribe token: an HMAC of the subscriber id (key from `TOKEN_PEPPER`), with only its hash stored, so every alert email can carry it. Rotating `TOKEN_PEPPER` breaks links already sent.
- Retention: unconfirmed signups are deleted after 30 days; unsubscribed rows are kept as the opt-out record; sent queue rows go after 90 days (`docs/architecture/operations.md`).
- CSV: active subscribers only (`email`, `confirmed_at`), formula-safe, audited with the staff email.
- Copies, not shared code: `services/turnstile.js`, `cleanEmail` and the CSV cell (modules can't import other modules' services).
- Alerts reads `Listing` (public fields only) in its own `services/facts.js`, as contact, payments and publishing do.
