Start with `/implement-ticket F03-T4`.

Added 2026-10-06 while planning F05-T1. Only the hash of a seller link is stored, so staff screens and scheduled jobs can't put the seller's link in an email. Instead of issuing a new link for every email, each seller keeps their one link, emails that can't carry it point to a "Get my link" page (F04-T3), and that page emails fresh links on request.

## Scope

- [x] New email `seller_link_request` (audience seller, transactional, sensitive): a list of the seller's open listings, each with title, status line and its own private link; at most 20 rows, with a "contact OCP" line when there are more. Plain-text and HTML versions; every value escaped.
- [x] `changes_requested` and `draft_reminder`: `seller_link` becomes optional. When it is missing the email says to use the link from the invitation email.
- [x] A shared "Can't find your private link? Get it here: {{get_link_url}}" line, placeholder `get_link_url` (the storefront URL of `/apps/classifieds/my-link`), on the seller emails that point the seller back to their page: `changes_requested`, `draft_reminder`, `listing_live`, `expiry_reminder`, `revision_rejected`.
- [x] Update the default templates, samples and the Settings → Emails preview; templates staff already customised keep working (the new placeholder is optional).

## Out of scope

- The "Get my link" page, link replacement and rate limits (F04-T3).
- Sending these emails from staff actions (F05-T1) or schedules (F08).

## Acceptance criteria

- [x] `changes_requested` and `draft_reminder` render without `seller_link`; with it, the link is shown as before.
- [x] `seller_link_request` renders 1, 3 and 21 listings correctly (21 shows 20 plus the contact line); listing titles are escaped.
- [x] The help line appears with a valid `get_link_url` and never contains a seller link or token.
- [x] `npm run test:ai` is green for this feature.

## Notes

_Record decisions (`// DECISION:`), deviations and follow-ups here. Code review and security audits are run on demand (`/review-all`), not per ticket._

- The `get_link_url` value is built by the sender (access/console) from the shop's storefront domain; notifications only renders it.
- DECISION: `seller_link_request` rows are `{ title, status, date, seller_link }`: the status code and a date the sender formats (due or end date); the template turns them into words, so staff can edit them.
- DECISION: the 20-row cap and `more_count` are set inside notifications (`limits` in the registry, applied in `cleanVars`); a caller's `more_count` is ignored. Senders may pass up to 50 rows.
- DECISION: `listing_live`, `expiry_reminder` and `revision_rejected` also hide their manage link when `seller_link` is missing, so senders that only have the hash (F05, F08) never produce an empty link.
- DECISION: `get_link_url` must be https with the path exactly `/apps/classifieds/my-link` (`GET_LINK_PATH` in the registry) and no query or fragment, so it can't carry a token. F04-T3's `getLinkUrl()` must build exactly that.
- DECISION: stored templates that still hold an earlier default (kept in `emails/superseded.js`) move to the new default on first read, audited as `EmailTemplateDefaultsUpdated` (actor SYSTEM). Edited templates are never touched. Add the old wording there whenever a default changes.
- A required list (`listings`) counts as kept while the template has `{% for … in listings %}`; an empty required list is refused when sending.
- Tests: `app/modules/notifications/tests/seller-link-help.test.js` (148 green for the module; mutation-checked the path check and the cap).
- Manual QA (to run on the dev store): Settings → Emails: "Your private links" appears under Emails to sellers with a two-row preview; "Changes requested" and the other four show the help line in the preview and are not marked "customised".
- Follow-ups: F05-T1 / F08 pass `get_link_url` (from `access.getLinkUrl()`, F04-T3) and leave out `seller_link`.
