## Scope

- [x] Settings → Emails (`/app/settings/emails`): a list of **every** template in the registry (staff, seller, alerts and ops emails), grouped by who receives it, and the global settings form (sender name, reply-to, **staff notification address**, logo, button colour, footer, phone, support email, postal address), saved with validation and an audit entry.
- [x] Template editor (`/app/settings/emails/<key>`): subject and body, placeholder picker, preview, send test (to the signed-in staff email, or to another address staff type in), reset with a confirmation modal. Uses the template services from F03-T1.
- [x] An **Emails** button on the Settings page.

## Out of scope

- Sending, rendering, the SNS webhook and staff notices (F03-T1).
- Anything listed in other tickets or features.

## Acceptance criteria

- [x] Staff can change the staff notification address and the next staff notice goes there; an invalid address or logo URL is refused with a field error.
- [x] Editing a template on the screen applies to the next send; the preview shows sample data; a test email goes to the signed-in staff email unless staff type another address.
- [x] `npm run test:ai` is green for this feature.

Safeguards: the address is validated, only sample data is sent, each staff member can send 10 tests an hour (counted in the app process, so it resets on restart), and every test is audited as `EmailTestSent` with the template key, status and recipient.
