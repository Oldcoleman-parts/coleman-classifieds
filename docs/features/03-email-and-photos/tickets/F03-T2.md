## Notes

_Record decisions (`// DECISION:`), deviations and follow-ups here. Code review and security audits are run on demand (`/review-all`), not per ticket._

- Built as the new `media` module (no schema change; `Photo` already existed). Nothing changed in `notifications`.
- The bucket, Block Public Access, CloudFront OAC, lifecycle rules, CORS and the per-prefix IAM policy are AWS console work, written up in `docs/reference/s3-cloudfront-setup.md`. The repo has no infrastructure code.
- DECISION: the two upload routes (`/apps/classifieds/upload-url`, `/apps/classifieds/upload-complete`) are **not** built here. The “token checks” need the seller sign-in from F04, and a route without it would hand upload links to anyone. `createUploadUrl()` and `completeUpload()` take a listing the caller has already checked, plus the actor (SELLER or STAFF). Follow-up on F04-T2.
- DECISION: sharp’s ready-made builds can’t read HEIC, so HEIC is decoded with `heic-decode` (pure JavaScript, a few seconds for a phone photo) and then goes through the same sharp re-encode. The pixel count is checked before decoding.
- DECISION: the upload link signs the content type and the exact content length, so S3 refuses a different type or size. The size and real type are checked again when the upload is completed.
- DECISION: a deleted photo’s stored file is removed at once (bucket versioning keeps it recoverable for 30 days), so `deletedAt` always means the file is gone.
- DECISION: retention needs the close date, so `core.getListingSummary()` now also returns `closedAt` (approved in the plan). The task is `media.purge-closed-photos`.
- DECISION: public copies get a new random name on every publish, unrelated to the photo id, and are cached as immutable; unpublish deletes them and invalidates CloudFront.
- Limits (`services/limits.js`): JPEG, PNG, WebP, HEIC; 15 MB; 50 megapixels; stored long edge 2560 px; public sizes 320, 800 and 1600 px.
- `publish(listingId, { photoIds })` can publish only an approved revision’s photos. The event listeners publish every current photo of the listing; F04 must delete (or not attach) a rejected revision’s new photos so they are never published.
- A failed photo publish only logs the photo id for now; F08 turns it into a PUBLISHING incident.
- Manual checks still open (need AWS): section 8 of `docs/reference/s3-cloudfront-setup.md`, including “a direct S3 address for `private/` answers 403”, which can’t be tested without a real bucket.
- Close attempted on 2026-10-05 and stopped: two criteria are not covered yet. (1) HEIC with GPS: the test in `tests/process.test.js` is skipped until a real phone photo is saved as `app/modules/media/tests/fixtures/gps.heic`. (2) No public access to `private/`: needs the real-bucket checks in section 8 of `docs/reference/s3-cloudfront-setup.md` (steps 2 and 3) recorded here. Tested so far: media 83 passed, 1 skipped.
