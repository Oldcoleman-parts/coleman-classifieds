## Notes

_Record decisions (`// DECISION:`), deviations and follow-ups here. Code review and security audits are run on demand (`/review-all`), not per ticket._

- From F03-T1: going live sends `listing_live` (`expires_date`, `listing_url`, `seller_link`) with `notifications.send(key, to, vars, { replyTo, idempotencyKey })`; see `app/modules/notifications/registry.js`. Both links must be https. A `sensitive` template (private link) is never queued: `send()` returns `{ status: "FAILED" }` if SES is down, and the caller must cope (retry later).
- From F03-T2: the metaobject’s `photos` field takes `await media.publish(listingId)` (safe to repeat; returns the CloudFront `_large` addresses, main photo first) or `media.getPublicUrls(listingId, size)`. Media also publishes on `ListingWentLive`, but listener order isn’t guaranteed, so call `publish()` before the upsert rather than relying on it.
- From F03-FIX-2: `publish()` and `getPublicUrls()` return staff-approved photos only, and `publish()` returns `[]` for a closed listing. Still call `publish()` before the upsert.
