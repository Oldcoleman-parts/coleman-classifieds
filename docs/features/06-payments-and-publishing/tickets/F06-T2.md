## Notes

_Record decisions (`// DECISION:`), deviations and follow-ups here. Code review and security audits are run on demand (`/review-all`), not per ticket._

- From F03-T1: going live sends `listing_live` (`expires_date`, `listing_url`, `seller_link`) with `notifications.send(key, to, vars, { replyTo, idempotencyKey })`; see `app/modules/notifications/registry.js`. Both links must be https. A `sensitive` template (private link) is never queued: `send()` returns `{ status: "FAILED" }` if SES is down, and the caller must cope (retry later).
- From F03-T2: the metaobject’s `photos` field takes `await media.publish(listingId)` (safe to repeat; returns the CloudFront `_large` addresses, main photo first) or `media.getPublicUrls(listingId, size)`. Media also publishes on `ListingWentLive`, but listener order isn’t guaranteed, so call `publish()` before the upsert rather than relying on it.
- From F03-FIX-2: `publish()` and `getPublicUrls()` return staff-approved photos only, and `publish()` returns `[]` for a closed listing. Still call `publish()` before the upsert.
- From F04-FIX-1: event handlers run in subscription order. Register publishing **after** workspace in `app/bootstrap.server.js`, so on `RevisionApproved` it reads the title and description workspace has just copied. Alternative if that is fragile: have workspace publish `ListingUpdatedImmediate { fields: ['title','description'] }` after copying.
- From F05-T2: Health shows the live count in the app only. Export the storefront live count from `publishing` and register it with `console.setHealthProviders({ liveCount: { getStorefrontCount } })` so the two can be compared.
- F06-T2 dev-store QA: API 2026-10 titles the Online Store catalog "Channel Catalog <id> for Online Store", so fee setup failed with `FEE_CHANNEL`. `publishFeeProduct()` now matches both forms (`payments/services/setup.js`).
- F06-T2 dev-store QA: Shopify deleted the app's storefront token (scope re-auth) while the settings kept it, so `cartCreate` failed with `UNAUTHORIZED`. `createCheckout()` now discards a refused token (`discardStorefrontToken()`, audit `StorefrontTokenDiscarded`), creates a new one and retries once.
- F06-T2 dev-store QA: the theme editor did not offer the "Classified listing" block on the metaobject template while its schema had `"templates": ["metaobject"]`; the limit was removed (the block renders nothing outside a listing page).
