## Problem

Console `services/history.js` reads core's `AuditEvent` table directly (rule 00), and since F05-T3 also runs a `groupBy` of every action over the whole table on each History page load.

## Scope

- [x] `core/audit.js`, exported from `index.js`: `listAuditEntries({ listingId?, start?, end?, action?, actor?, actorRef?, after?, take })` (newest first, keyset on `(at, id)`, at most 200 a call, listing title included), `streamAuditEntries(filter)` or a batch reader for the CSV (oldest first, in `(at, id)` order, bounded by the newest row at the start), and `listAuditActions()` (the distinct actions, cached for a short time or from a fixed registry; say which).
- [x] Migration `audit_event_at_index`: `@@index([at, id])` on `AuditEvent` for date-only filters (`/schema-change`; note the brief write lock and that a human runs it in production).
- [x] Lows from review 8: pin `search_path` on `audit_event_append_only()` in the same migration; record the runtime-role-owns-`AuditEvent` risk in `docs/architecture/operations.md`; keep `PrivacyErased` and `privacy.*` rows in the listing-less retention (or a DECISION) and update `.claude/rules/jobs-and-ops.md` to match the purge rule.
- [x] Update core `CLAUDE.md` and `data-model.md`.

## Out of scope

- Moving console onto the helpers (F05-FIX-1).

## Acceptance criteria

- [x] Each filter and the keyset paging return exactly the matching entries in order (test).
- [x] The action list has every action once and doesn't scan the table on each call (test).
- [x] Invalid input is a `ValidationError` (test).
- [x] `npm run test:ai -- app/modules/core` is green.

## Notes

_Record decisions (`// DECISION:`), deviations and follow-ups here._

- Built: core `audit.js` `listAuditEntries(filter, { after, before, take })` (newest first, `(at, id)` cursors `<ms>_<id>` both ways, at most 200, with the listing title), `openAuditExport(filter, { batchSize })` (oldest first, ending at the newest entry when opened; the bound and cursor logic of console's CSV stream now lives here), `listAuditActions()` (exported from `index.js`; `clearAuditActionCache()` from `audit.js` for tests), the `AuditFilter` / `AuditEntry` typedefs in `types.js`. `writeAudit` / `recordEvent` call `noteAuditAction()`. Migration `20261027113003_audit_event_at_index` (`@@index([at, id])`; `ALTER FUNCTION audit_event_append_only() SET search_path = pg_catalog, <schema>`). Console is unchanged (F05-FIX-1).
- `// DECISION:` these History reads return `details` and `actorRef` (unlike the F01-FIX-10 counts): staff-only protected history, never public output. A listing's timeline is `listAuditEntries({ listingId }, { take: 200 })` reversed, so no extra function.
- `// DECISION:` the action list is cached in memory for 5 minutes (single-flight) rather than a fixed registry: actions are written from many places, some built at runtime, and old rows must stay filterable. The read is a loose index scan on `[action, at]`. An action written during a load or by another process shows within 5 minutes; a rolled-back write can briefly offer a filter that matches nothing.
- `// DECISION:` `search_path` is `pg_catalog` first, then the app schema (the reverse of the review's suggestion), so no app table can shadow a built-in.
- `// DECISION:` the purge keeps `PrivacyErased` and `privacy.*` rows for good, as the proof a redaction was done (ids and counts only). `.claude/rules/jobs-and-ops.md` now states the actual retention rule (user-approved edit of the rule file); `operations.md` records the runtime-role-owns-`AuditEvent` accepted risk.
- Migration note: the plain `CREATE INDEX` briefly blocks audit writes while it builds (small table); a human runs `prisma migrate deploy` in production (add to F08-T2's database check). No Shopify re-auth or deploy.
- Tests: `core/tests/audit-list.test.js`, `audit-validation.test.js`, `audit-export.test.js`, `audit-actions.test.js`, `audit-retention.test.js`; `audit-append-only.test.js` gained the pinned `search_path` check. `npm run test:ai -- app/modules/core` → `✓ 287 passed · 0 failed`; `npm run test:ai -- app/modules/ops` → `✓ 80 passed · 0 failed`.
