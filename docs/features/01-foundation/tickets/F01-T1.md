## Scope

- [x] **Database:** switch the Prisma datasource from SQLite to **PostgreSQL** (`DATABASE_URL`), keeping the template `Session` model as is. Add a local Postgres option (Docker compose or a Railway dev database) and document it in `docs/reference/local-setup.md`.
- [x] **Schema:** add every model from `docs/architecture/data-model.md` to `prisma/schema.prisma`, and create the initial project migration, including the AuditEvent append-only trigger and the retention purge role (raw SQL in the migration).
- [x] **Conventions (JavaScript):** create the `app/modules/` layout (`platform`, `core`, `scheduler`, each with `index.js`); `core/errors.js` (custom error classes), `core/types.js` (JSDoc `@typedef`s from the data model) and small input validators; keep route files thin; add the `@/` path alias if the template doesn’t have one. - [x] **Tooling:** Vitest (+ a test database setup), shared factories in `tests/factories.js` (`makeListing`, `makeInvitation`, `asSeller`, `asStaff`, `mockShopify`, `mockSes`, `mockS3`); package scripts `test:ai` (`node scripts/test-summary.mjs`), `test`, `lint`; reuse the template’s ESLint and Prettier config; a CI workflow running lint and `test:ai`.

**Decisions**

- **Local database:** Docker compose (`docker-compose.yml`, PostgreSQL 16); a Railway dev database is documented as the alternative in `docs/reference/local-setup.md`.
- **Template SQLite migration:** deleted and re-created for PostgreSQL. It had only been applied to the local, git-ignored `prisma/dev.sqlite`. The app re-authenticates on first open because the `Session` table starts empty.
- **Migrations were generated without a database** (`prisma migrate diff`), then the raw SQL was appended by hand. They were checked by applying both to an in-memory PostgreSQL (PGlite): UPDATE, DELETE and TRUNCATE on `AuditEvent` are rejected; DELETE as `classifieds_purge` is allowed.
- **Purge role:** `classifieds_purge`, `NOLOGIN`, used through `SET LOCAL ROLE`. The trigger checks the role only; the `purgeAfter` rule is F08 code.
- **TRUNCATE** on `AuditEvent` is also blocked (the docs name only UPDATE and DELETE). The test reset bypasses triggers with `session_replication_role`, so the test database user must be a superuser.
- **Test database:** a separate `classifieds_test` database; migrated once per run, truncated per file, files run serially. The run refuses a database whose name doesn’t end in `_test`.
- **Module skeleton:** `index.js` and `tests/` only. `events.js`, `services/` and `routes/` come with F01-T2.
- **Validators:** hand-written in `core/validators.js`, no schema library.
- **Typedefs:** `core/types.js` aliases the Prisma-generated types rather than repeating fields.
- **`tsconfig.json`:** kept (the template ships it); only the `@/*` path was added. The alias itself is set in `vite.config.js` and `vitest.config.js`.
- **Node:** `Dockerfile` moved from `node:20-alpine` to `node:22-alpine`; CI uses Node 22.
- **Staging:** a separate Shopify app (`shopify.app.staging.toml`), so dev and staging URLs don’t overwrite each other.
- **`.env.example` was not created:** the project’s permission rules block writing `.env*` files. The variable list is in `docs/reference/local-setup.md` instead.

**Differences from the template:** `prisma/schema.prisma` (datasource and new models; `Session` unchanged), `vite.config.js` (alias), `tsconfig.json` (paths), `.eslintrc.cjs` (Node override covers modules and tests), `package.json` (`test`, `test:ai`, `vitest`), `Dockerfile` (Node 22), `.dockerignore`. Auth, routes, `shopify.app.toml` and `shopify.web.toml` are untouched.
