Start with `/implement-ticket F01-T1`. **The app already exists**: begin by listing what the template already provides (with file paths), then plan only the changes below. Don’t re-scaffold, re-init, or rewrite the template’s auth or session code.

## Scope

- [ ] **Database:** switch the Prisma datasource from SQLite to **PostgreSQL** (`DATABASE_URL`), keeping the template `Session` model as is. Add a local Postgres option (Docker compose or a Railway dev database) and document it in `docs/reference/local-setup.md`.
- [ ] **Schema:** add every model from `docs/architecture/data-model.md` to `prisma/schema.prisma`, and create the initial project migration, including the AuditEvent append-only trigger and the retention purge role (raw SQL in the migration).
- [ ] **Conventions:** create the `app/modules/` layout (`platform`, `core`, `scheduler`, each with `index.ts`); keep route files thin; add the `@/` path alias if the template doesn’t have one. Move nothing from the template that other template files depend on.
- [ ] **Tooling:** Vitest (+ a test database setup), shared factories in `tests/factories.ts` (`makeListing`, `makeInvitation`, `asSeller`, `asStaff`, `mockShopify`, `mockSes`, `mockS3`); package scripts `test:ai` (`node scripts/test-summary.mjs`), `test`, `typecheck`, `lint`; reuse the template’s ESLint and Prettier config; a CI workflow running lint, typecheck and `test:ai`.
- [ ] **Hosting:** an OCP-owned Railway project (app service + Postgres + hourly cron calling `/jobs/run`); env vars from `docs/architecture/shopify-config.md`; make sure the template’s `setup` script (`prisma generate && prisma migrate deploy`) runs on deploy; a staging app config (`shopify.app.staging.toml`) pointing at the Railway URL.

## Out of scope

- Shopify scopes, webhooks and app proxy changes, and the lifecycle logic (F01-T2).
- Any feature logic.

## Acceptance criteria

- [ ] The app still installs, authenticates and opens embedded on the dev store (no regression from the template).
- [ ] `prisma migrate deploy` runs cleanly on an empty PostgreSQL database, and the `Session` table works with the template auth.
- [ ] UPDATE on AuditEvent fails at the DB level.
- [ ] `npm run test:ai` prints the one-line summary; CI passes lint, typecheck and tests.
- [ ] The staging deploy on Railway opens in the dev store admin.
