## Scope

- [ ] **`shopify.app.toml`:** add the access scopes, webhook subscriptions (`orders/paid`, `refunds/create`, plus the mandatory privacy webhooks next to the template’s `app/uninstalled` and `app/scopes_update`) and the app proxy (`apps/classifieds`), as listed in `docs/architecture/shopify-config.md`. Apply with `shopify app deploy` (done by a human) or `shopify app dev` for the dev store.
- [ ] **Platform module:** `adminGraphql()` and `storefrontGraphql()` helpers that throw on `userErrors`; a webhook router on top of `authenticate.webhook` with `WebhookReceipt` idempotency; an app proxy wrapper on top of `authenticate.public.appProxy`; privacy webhook handlers.
- [ ] **Core lifecycle:** `transition(listingId, event, actor, payload)` implementing the whole state machine table (deadlines, pause reasons, adjustments, terminal states with `purgeAfter`, Phase 2 states); a typed event bus that writes the audit entry before handlers run; `flags.isEnabled()` plus release gates; the `Settings` singleton with defaults; `addMonths` in the shop timezone; `adjustTime()`.
- [ ] **Scheduler skeleton:** `/jobs/run` (bearer secret) with a task registry and a per-task result summary. Later features add tasks.

## Out of scope

- Any feature screens or feature-specific tasks.

## Acceptance criteria

- [ ] The new scopes are granted on the dev store (re-auth prompt accepted), and the app still opens.
- [ ] A duplicate webhook delivery is ignored; an invalid HMAC is rejected; an unsigned proxy request is rejected.
- [ ] Every allowed transition is covered (`it.each`), and at least 10 invalid transitions or wrong actors are rejected.
- [ ] Approving a revision never changes `expiresAt` or reopens a terminal listing. Jan 31 + 1 month = Feb 28/29. An investigation restore adds exactly the paused minutes.
- [ ] `/jobs/run` without the secret → 401; with it → a JSON summary.
