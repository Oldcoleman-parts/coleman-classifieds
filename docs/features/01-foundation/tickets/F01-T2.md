**Decisions**

- **Scopes:** 9 of the 11 scopes were added. `write_purchase_options` and `write_own_subscription_contracts` are renewals-only and are deferred to F08 (approved by the developer, 2026-10-05); `docs/architecture/shopify-config.md` says so.
- **Shop timezone:** read from `SHOP_TIMEZONE` (IANA name), default `America/New_York`. OCP must confirm the zone before launch.
- **New event `ListingPaymentOverdue`** (LIVE → PAYMENT_OVERDUE), and `expiresAt` added to the `ListingWentLive` payload; both are in `docs/architecture/events.md`.
- **State machine gaps:** the table had no rows for re-issuing a lapsed listing or rejecting a revision; both were added to `docs/architecture/data-model.md`, with a section on how `transition()` reads the table (actors for sold/removed, paused listings not expiring, fixed 24-hour day windows, whole-minute restores, the 60-day extension limit, `closedReason` values).
- **Resume after an investigation** requires `violation: true | false`; it never defaults to restoring time.
- **A rejection publishes `ListingRejected` only**, not `ListingClosed` as well.
- **Concurrency:** `transition()` locks the listing row (`SELECT … FOR UPDATE`), so two events for one listing apply one after the other.
- **Event bus:** the audit row is written in the same transaction as the status change; handlers run after commit, and a failing handler is logged and isolated. It does not undo the change.
- **`adjustTime()`** is the public entry point for technical extensions and runs the `EXTEND` event. Investigation restores happen inside `RESUME`.
- **`core.writeAudit()`** was added for audit entries that aren’t bus events (staff actions, privacy requests). Callers pass IDs, statuses and dates only.
- **Settings:** there is no seed script; `getSettings()` creates row 1 on first read, with placeholder rules text (`rulesVersion` `draft-0`).
- **Webhook auth:** the Shopify helper answers 400 when the signature header is missing; `handleWebhook()` returns 401 for that as well as for a bad HMAC. The two template webhook routes are left as they are (already idempotent).
- **App proxy:** the Shopify helper answers 400 for a bad signature and rejects timestamps older than 90 seconds; `withAppProxy()` returns 401 for both, and for a shop without a session. The proxy URL is `<app URL>/proxy`.
- **Privacy webhooks:** verified, de-duplicated and written to the audit log with IDs only; `shop/redact` also deletes the shop’s sessions.
- **`/jobs/run`:** POST only (GET → 405). A failing task is reported in the summary with HTTP 200. There is no lock against overlapping runs; tasks must be idempotent.
- **Bootstrap:** `app/bootstrap.server.js` (imported by `app/entry.server.jsx`) resets the registries and calls each module’s `register()`, so a dev reload doesn’t double-register.
- **Dependencies added:** `date-fns`, `@date-fns/tz`.

**Differences from the template:** `app/entry.server.jsx` (one import line), `shopify.app.toml` (scopes, three webhook subscriptions, `[app_proxy]`). `app/shopify.server.js` and the template routes are untouched.
