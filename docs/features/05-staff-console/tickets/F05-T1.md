## Notes

_Record decisions (`// DECISION:`), deviations and follow-ups here. Code review and security audits are run on demand (`/review-all`), not per ticket._

- From F03-T1: emails are sent with `notifications.send(key, to, vars, { replyTo, idempotencyKey })` (keys and placeholders in `app/modules/notifications/registry.js`). Request changes sends `changes_requested`, Reject sends `listing_rejected`, and revision decisions send `revision_approved` / `revision_rejected`.
- From F03-T1: the staff-notice review links already point at `/app/listings/<id>` and `/app/messages`, so those routes must exist with exactly those paths.
- From F03-T2: the review screen’s photos use `media.listPhotos()`, `media.reorder()`, `media.setMain()` and `media.deletePhoto()` with the staff actor, and `uploadPhoto()` from `app/modules/media/client.js` if staff can add photos. Preview links are private and last 10 minutes.
- From F03-FIX-2: Approve must call `transition(id, APPROVE, staff, { photoIds })` with the ids of the photos staff saw on the review screen (may be empty); only those are ever published. Approving a revision passes `{ revisionId, photoIds: revision.photoIds }`. A missing `photoIds` is refused. `media.listPhotos()` returns `approved` so the screen can show which photos are awaiting review. Photos staff add to a live listing are not approved automatically: decide the path here.
- From F04-FIX-1: workspace applies revision decisions. Call `transition(listingId, APPROVE_REVISION | REJECT_REVISION, staff, { revisionId, photoIds })` only for a PENDING revision of that listing (core accepts any revisionId); `photoIds` are the revision photos staff approved. On approval workspace copies title/description into the listing; on rejection it deletes the revision's never-approved photos. Photos not approved in a partial approval stay unapproved and come back in the seller's next revision.

Plan defaults agreed: staff wording edit by console (SUBMITTED only, audited), read-only payment panel until F06, staff photo uploads only while SUBMITTED, `revision_approved` skipped until a listing URL exists (F06).
